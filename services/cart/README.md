# Nivaro Cart

P05 foundation. The service owns its PostgreSQL database and stores guest/customer owner identities, per-market carts, stable line IDs, component groups, private build drafts and idempotency records. No foreign keys reference another service's database. Transferred group provenance survives source draft deletion. A composite foreign key prevents assigning a line to a group in another cart, and a partial unique index keeps standalone lines unique per variant while allowing that variant in multiple groups.

Only liveness and schema readiness are exposed at this checkpoint. Browser cart/build operations, guest cookies, the authenticated identity bridge, merge/transfer transactions and the cart UI remain P05 work. No runtime gateway route is enabled until authorization is implemented.

Run `scripts/Verify-CartFoundation.ps1` with the prepared Linux environment, or pass `-TestImage nivaro-cart:test`. Tests use a uniquely named internal network and disposable PostgreSQL memory volume. They verify migration repeatability, schema drift, role/database isolation, group ownership, duplicate line/operation constraints, draft/group separation and aggregate cart limits.

The internal mutation module locks the owning cart, compares its expected version and validates the entire proposed snapshot through `validate_quantities` before flushing. Its caller must supply the authenticated owner and an enclosing transaction; it is not a replacement for HTTP authorization or catalog validation. Loose additions preserve same-SKU group lines. Quantity/removal operations address stable line IDs, require a group revision for group children and advance the group revision when changed. Removing a required slot leaves an incomplete group; deleting a group cascades only its own children. Future merge/transfer writers must follow the same lock ordering. A real two-connection test observes the competing PostgreSQL lock and verifies a stale write cannot double quantities.

Default limits are 50 variants, 100 lines and 20 units per variant across all groups and loose lines. Configure them through `CART_MAX_VARIANTS`, `CART_MAX_LINES` and `CART_MAX_UNITS_PER_VARIANT`; database constraints enforce positivity while the aggregate application check uses the configured limits. Saving lines has no stock-reservation effect. Account-cart retention is indefinite until owner deletion or a separately specified retention policy. Guest cleanup may apply the roadmap's 30-day inactivity interval after the owning session and cleanup workflows are implemented.
